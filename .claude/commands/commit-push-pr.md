## Goal

"Commit, push, and open a PR" - Automate the core daily workflow into a single command.

## Pre-Requisites

Recommend verifying changes with `/verify` before running:

```
/verify → confirm pass → /commit-push-pr
```

## Execution Steps

### 1. Analyze (using Pre-computed Context above)

### 1.5 Pre-commit Verification (high-priority projects only)

Detect projects from changed files and check tier in CLAUDE.md project table.
**If high-priority project changes are included**, run automatic verification before commit:

```bash
cd <project-dir>
npx tsc --noEmit          # Block commit on failure
npm run lint               # Block commit on failure
npm test 2>/dev/null       # Warning only (does not block)
```

- TSC/Lint failure: Block commit, suggest fixes
- Test failure: Show warning, ask user whether to proceed
- Lower-tier projects: Skip this step

### 2. Analyze Changes

Analyze changed files to determine:

- Change type (feature, fix, refactor, docs, test, chore)
- Summary of key changes
- Affected projects/modules

### 3. Generate Commit Message

#### Conventional Commits Format

```
<type>(<scope>): <subject>

<body>

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>
```

#### Type Classification

| Type     | When to Use                           |
| -------- | ------------------------------------- |
| feat     | New feature                           |
| fix      | Bug fix                               |
| refactor | Code refactoring (no behavior change) |
| docs     | Documentation changes                 |
| test     | Adding/modifying tests                |
| chore    | Build/config changes                  |
| style    | Formatting (semicolons, spaces, etc.) |
| perf     | Performance improvement               |

#### Scope Examples

- Project name: e.g., `auth-service`, `dashboard`, `api`
- Module name: `auth`, `api`, `ui`, `functions`

### 4. Execute Git Operations

```bash
# Step 1: Stage all changes
git add -A

# Step 2: Create commit
git commit -m "$(cat <<'EOF'
<type>(<scope>): <subject>

<body - detailed changes>

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>
EOF
)"

# Step 3: Push to remote
git push origin $(git branch --show-current)

# Step 4: Verify commit success
git status
```

### 5. Create PR (Optional)

If user requests PR creation or on a feature branch:

```bash
# Create PR
gh pr create --fill

# Or with detailed info
gh pr create --title "<PR title>" --body "$(cat <<'EOF'
## Summary
<1-3 bullet points>

## Changes
- <Key change 1>
- <Key change 2>

## Test Plan
- [ ] Unit tests pass
- [ ] E2E tests pass (if applicable)
- [ ] Manual testing complete

🤖 Generated with [Claude Code](https://claude.com/claude-code)
EOF
)"
```

## Options

### Basic Usage

```bash
/commit-push-pr
# → Auto-generate commit message, push, ask about PR creation
```

### Specify Commit Message

```bash
/commit-push-pr "fix: resolve login redirect issue"
# → Commit with the specified message
```

### Commit Only (no push/PR)

```bash
/commit-push-pr --commit-only
```

### Push Only (no PR)

```bash
/commit-push-pr --no-pr
```

### Force PR Creation

```bash
/commit-push-pr --with-pr
```

### WIP Commit

```bash
/commit-push-pr --wip
# → Commit with "wip: <auto-generated description>" format
```

## Safety Checks

### Pre-commit Checks

- [ ] No files containing sensitive information (.env, credentials.json, etc.)
- [ ] Build files/node_modules excluded
- [ ] No unintended file changes

### Warning Situations

```
⚠️ The following files need attention:
- .env.local (potential sensitive information)
- package-lock.json (confirm intentional change)

Proceed?
```

### Prohibited Actions

- Sensitive files like `.env`, `credentials.json` are blocked from commit
- `--force` push only when explicitly requested by user

## Project-Specific Notes

### Firebase Projects

- Recommend `npm run build` before commit
- Notify about separate deployment needed when functions/ changes

### Submodule Projects

```bash
# When submodule changes, commit separately inside the submodule
cd <submodule-dir>
git add -A && git commit -m "<message>"
git push origin main
cd ..
git add <submodule-dir>
git commit -m "chore: update submodule"
```

### Monorepo Projects

- Specify changed workspace: `feat(web):`, `feat(mobile):`, `feat(shared):`
